# FFmpeg loudnorm: cache 100 ms block energies so Plex loudness analysis runs many times faster with identical results
Status: approved
Issue: diblaze/media_preview_generator#2 (build half; the research half is plans/loudness-ebur128-parity.md)
## Goal

2. docker/ffmpeg-loudnorm/0001-avfilter-ebur128-cache-100ms-block-energies.patch — ebur128.c only (E8). `FFEBUR128StateInternal` gains `double *block_energy` (`audio_data_frames / samples_in_100ms` blocks x channels), `uint64_t *block_id` (which absolute 100 ms block a slot holds; init `UINT64_MAX`), `uint64_t frames_total` (incremented in both branches of `ebur128_add_frames_planar`). `ebur128_calc_gating_block(st, n, out)` becomes: window `[frames_total - n, frames_total)` clamped at 0 (frames before the first are the ring's zeros today); per channel `energy = partial(head) + sum of full 100 ms blocks + partial(tail)`, a full block read from the cache when `block_id[slot] == block`, else summed from the ring once and cached; `partial()` is today's sample loop over a sub-block range (ring index = absolute frame mod `audio_data_frames`); the `1.41` / `2.0` weights and `/= n` unchanged. Per-channel summation order inside a block is today's; only the association across blocks changes, so values differ at most in the last bits ("exact up to floating-point summation order"). `ebur128_energy_in_interval` keeps its `interval_frames > audio_data_frames` guard. Frees in `ff_ebur128_destroy`. ~80 lines. (E5-E7)

## Deferred (YAGNI)
- Drop the stage, `build.sh`, patch and `binary()` — reopen when `/usr/lib/jellyfin-ffmpeg/ffmpeg -version` reports an FFmpeg release that contains the upstream commit.
- FATE test for loudnorm (needs a fate-suite sample and reference, E13) — reopen if FFmpeg reviewers ask.
- Rebuilding jellyfin-ffmpeg's deb or swapping its `libavfilter.so.11` — rejected: hours of build and jellyfin's tonemap patches live in that library (E4:111-112); reopen only if stock 8.1.3 fails parity against jellyfin-ffmpeg on the 15 tracks (decoder mismatch).
- Sliding add/subtract running sum (O(1) per sample) — rejected: cancellation drift over hours, not "exact up to order"; no reopen trigger.
- SIMD for the per-block sum or skipping the 192 kHz upsample — reopen if the post-patch profile still shows >20% in `ebur128_calc_gating_block` or `swr`; the resampler must stay default regardless (E11).
- A UI setting to pick the binary — reopen if someone needs the slow path for a bug-for-bug comparison (deleting the binary already falls back, item 5).
- Backport request to `release/8.1` — reopen if FFmpeg maintainers treat it as a fix; the image builds its own 8.1.3 either way.
