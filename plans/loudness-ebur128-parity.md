Acceptance (per field, |Δ| against stored, max over the whole sample, per variant):
- loudness ≤ 0.10 LU (EBU Tech 3341 meter tolerance; 10 LSB of Plex's 0.01 store, E3).
- lra ≤ 0.10 LU (stored values are x.x0 — loudnorm prints LRA at 0.1 granularity — so this is "same LSB"; Tech 3342's ±1 LU would be far looser, the issue asked 0.1).
- peak ≤ 0.10 dB (F2 already shows 0.45 dB Plex-vs-app on one EAC3 2.0 track; report EAC3 separately and note sample-peak vs true-peak which is closer).
- threshold ≤ 0.10 LU on the M-derived value; summary value must agree with it within 0.05 (self-check).
- gainOffset "derivable" = H1 or H2 residual max ≤ 0.01 on 631 rows (exact to Plex's LSB); "approximate" = p95 ≤ 0.10; else "not derivable".
Decision: GO iff (a) one variant passes all four fields on every codec, (b) that variant is ≥ 10× faster than loudnorm on the timing subset (if only V2 passes, its 192 kHz cost is the number that matters), (c) gainOffset is derivable exactly, or Step 0 shows nothing is computed from it. Otherwise NO-GO, with the per-codec table saying which field broke it (a codec-restricted GO, e.g. stereo-only, is reported as its own row for the user to decide).

## Findings (2026-10-04)
- Parity, 15 Plex-analysed tracks (eac3/6 ×3, eac3/2 ×2, ac3/6 ×2, ac3/2, dca/6 ×2, truehd/8, aac/2 ×2, opus/2, mp3/2), native `ebur128=peak=true`: |Δ| max/mean loudness 0.29/0.04, lra 0.40/0.11, peak 0.45/0.07, threshold 0.28/0.05. Only truehd/8 exceeds 0.1 on loudness/threshold (+0.29/+0.28). 192 kHz variant: loudness 0.26/0.02, no better on lra/peak. Speed under load: native median 14× realtime (5–67×), 192k median 10×; loudnorm ≈4.3×.
- Step 0: Plex uses `ln:gainOffset` at playback. Captured Plex Transcoder for Ad Astra (stored gainOffset 2.69) with Normalize Loudness on: `loudnorm=I=-16:TP=-1:LRA=9:measured_I=-17.74:measured_LRA=23.30:measured_TP=2.74:measured_thresh=-30.27:offset=2.69:linear=true`.
- What loudnorm does with it (FFmpeg master `libavfilter/af_loudnorm.c` init/config_input): linear mode only when `measured_TP + (I − measured_I) ≤ TP` and `measured_LRA ≤ LRA`, and then `offset` is overwritten by `I − measured_I` (gainOffset ignored). Otherwise loudnorm falls back to dynamic and `offset` is a fixed pre-gain on every sample (gainOffset error = playback level error, 1:1). Live DB: 566 of 662 analysed tracks (85%) take the dynamic path; mean |gainOffset| 0.49 dB, range −1.27..+3.29.
- Tradeoff for the user: ebur128 reproduces the four input stats (≈3× faster than loudnorm under load) but not gainOffset; a fast mode must estimate it (0, or a fitted model), costing playback-level accuracy on 85% of tracks by the estimate's error (gainOffset=0: mean 0.49 dB, worst 3.3 dB).
